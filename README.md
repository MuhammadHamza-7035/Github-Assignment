In "git merge", the two branches are merged together into the one and the commit is neccassary for the merge to occur called the merge commit

And
In "git rebase", the branch base is completly lifted from the previous and is taken to the most recent commit and without any merge commits 
However
because it alters commit hashes, it can cause severe issues if used on branches that other developers are actively sharing and pulling from
